# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Talentcore — marketing site for an Azerbaijani recruitment / executive-search agency. Static HTML/CSS/vanilla JS with **no build step, no package manager, no tests, no dependencies**. Only external resources are Google Fonts: Poppins everywhere, plus Inter on `vacancies.html` only (added for the detail-panel title/company line during the DETAL DİZAYN TESTİ below).

To preview, open the `.html` files directly or serve the folder (`python -m http.server`). A server is preferable — `localStorage` and relative paths behave more predictably than under `file://`.

Primary content language is Azerbaijani (`<html lang="az">`), including code comments. Keep comments in Azerbaijani to match.

## Architecture

Each page is a standalone HTML file that loads `css/global.css` + its own page stylesheet, and `js/main.js` at the end of `<body>`. There is no templating — **both the `<header class="glass-header">` block and the `<footer class="site-footer">` block are duplicated verbatim in every page** (all 11: `index.html`, `about.html`, `services.html`, `vacancies.html`, `industries.html`, `contact.html`, `cv.html`, `faq.html`, `404.html`, `post-job.html`, `ad-banners.html`). Changes to nav, logo, FAQ link, theme toggle, language dropdown, or the footer (tagline/social icons/copyright) must be applied to every `.html` file. The header has **no CV button** — it was deliberately removed site-wide; `cv.html` still exists as a real page, just reached via in-content links (e.g. a vacancy detail's "Müraciət Et" button in `js/vacancies.js`, which links to `cv.html?company=…&vacancy=…`; with those params `js/cv.js` switches the page into an "apply to this vacancy" mode — see the `js/cv.js` bullet below), not from the header.

- `css/global.css` — theme CSS variables, header/nav, hamburger, theme switch, `.btn-primary`, the shared `.glass-effect` card component, the shared form components (`.form-row`, `.form-group` + its `input`/`select`/`textarea`/`input[type=file]` styling, `.form-note` + `.status-success`/`.status-error`, `.botcheck-field`) used by both `contact.html` and `cv.html`, the shared `.site-footer` component and the reusable `.faq-item` accordion component (native `<details>/<summary>` — no JS needed), and the shared responsive breakpoints (1024px, 768px). There is no more `.send-cv-btn` — it was removed along with the header CV button.
- `css/home.css`, `css/about.css`, `css/services.css`, `css/vacancies.css`, `css/industries.css`, `css/contact.css`, `css/cv.css`, `css/faq.css`, `css/notfound.css` — page-specific sections only (layout/hero/grid rules; the actual form-field and FAQ-accordion styling lives in `global.css`, see above). `home.css` no longer has a stats section (removed per request) — `.hero-baku` is now a single vertically-centered block (`justify-content: center` + a `margin-top` nudge on `.hero-content`), not a two-part flex layout.

Card padding/icon/text sizes use `clamp()` so the cards shrink to stay in one row rather than wrapping; the grid only drops to `repeat(2, 1fr)` at ≤1024px and `1fr` at ≤768px, once shrinking alone isn't enough. ### Theming

Dark is the default: `:root` holds the dark values, and `body.light-theme` overrides them. There is no `.dark-theme` rule in CSS — dark is simply the absence of `light-theme`.

### Language switching

The site has **four languages: AZ (default), EN, RU, ZH** — the `#lang-switch` `<select>` (in every page's header) has `AZ / EN / RU / ZH` options. `.lang` elements carry `data-az` and `data-en` attributes; **RU and ZH are NOT stored as attributes on the elements** — they live in one dictionary, `js/translations.js` (`window.TC_I18N`, `ru` / `zh` maps, plus an `en` map used only as a fallback for elements without `data-en`), **keyed by the element's `data-az` text** (AZ is the single source of truth). `js/translations.js` is loaded before `js/main.js` on every page (all 11). On change, `main.js` sets `<html lang>` first, then for each `.lang` element sets `innerHTML` from `window.tcText(el, lang)`: az → `data-az`; en → `data-en` (or the `en` dictionary entry, or `data-az`); ru/zh → dictionary entry for that `data-az`, falling back to `data-en`, then `data-az`. Placeholders use `tcPlaceholder` (`.lang-placeholder`, keys = `data-az-placeholder`). Strings built in JS (form status messages in `js/cv.js`/`js/contact.js`, the services showcase in `js/vacancies.js`, cv.js's apply-mode text via `setLang()`) go through `window.tcMsg(az, en)` — AZ text as the dictionary key, EN passed inline — so their RU/ZH entries must also be in `translations.js`. Consequences to respect:

- Values are injected as HTML, so `<br>` inside them works (used in the hero headline) — but the attributes are the translation source and must stay HTML-safe.
- **Dictionary keys are CASE-SENSITIVE exact copies of the `data-az` text** — e.g. `Müraciət Et` (vacancy detail) and `Müraciət et` (post-job button) are two different entries, as are `İxtisaslaşdığımız sahələr` (nav) and `İxtisaslaşdığımız Sahələr` (page heading); a case variant without its own entry silently falls back to English in RU/ZH.
- **When you add or change a `.lang` string, update THREE places: `data-az` + `data-en` in the HTML and the `ru` + `zh` entries (same `data-az` text as the key) in `js/translations.js`.** A missing RU/ZH entry silently shows English in those languages; a key that doesn't exactly match the `data-az` text (a typo, or an edited AZ string) breaks it the same way. `about.html` used to write the string `null` for EN on its 13 AZ-only elements; their EN is now supplied by the dictionary's `en` map (the elements themselves still only have `data-az` — fine, but give new elements both attributes).
- **Not translated (AZ-only, same as it was for EN):** the vacancy data and the text generated for vacancy cards/detail panels in `js/vacancies.js` (titles, descriptions, section headings, "Müraciət Et" on the detail, etc.), `<title>`/meta tags. Poppins (Google Fonts) has no Cyrillic/CJK glyphs, so RU/ZH text renders in the browser's fallback sans-serif font.
- **The chosen language is persisted** (`localStorage.lang`, saved by the `#lang-switch` change handler in `main.js`) and re-applied on every page load by `main.js`'s `applyLanguage()` before the page scripts run — previously it reset to AZ on every navigation (fixed on request: "başqa səhifəyə keçəndə dili nəzərə almır"). `js/cv.js`'s apply-mode `setLang()` therefore also renders through `tcText` instead of writing the AZ text, otherwise it would overwrite the restored language.
- The element's inline text should duplicate its `data-az` value, since that is what renders before any switch.

## Conventions

- Cards use `.glass-effect` (defined once in `global.css`, used across most pages), driven by `--card-bg` / `--card-hover` / `--border-color`.
- Accent color is `#c4642f` with `#b35624` for hover/border — hardcoded in `global.css` rather than tokenized.
- Sizing leans on `clamp()` for fluid type and spacing; prefer it over fixed px in new rules.
- `baku_light.jpg` is the hero background, set through the `--hero-bg` variable. `baku_light_2.jpg` is currently unreferenced.
