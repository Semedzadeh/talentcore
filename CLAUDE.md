# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Talentcore — marketing site for an Azerbaijani recruitment / executive-search agency. Static HTML/CSS/vanilla JS with **no build step, no package manager, no tests, no dependencies**. Only external resource is the Poppins webfont from Google Fonts.

To preview, open the `.html` files directly or serve the folder (`python -m http.server`). A server is preferable — `localStorage` and relative paths behave more predictably than under `file://`.

Primary content language is Azerbaijani (`<html lang="az">`), including code comments. Keep comments in Azerbaijani to match.

## Architecture

Each page is a standalone HTML file that loads `css/global.css` + its own page stylesheet, and `js/main.js` at the end of `<body>`. There is no templating — **both the `<header class="glass-header">` block and the `<footer class="site-footer">` block are duplicated verbatim in every page** (all 11: `index.html`, `about.html`, `services.html`, `vacancies.html`, `industries.html`, `contact.html`, `cv.html`, `faq.html`, `404.html`, `post-job.html`, `ad-banners.html`). Changes to nav, logo, FAQ link, theme toggle, language dropdown, or the footer (brand/social icons/copyright) must be applied to every `.html` file. The header has **no CV button** — it was deliberately removed site-wide; `cv.html` still exists as a real page, just reached via in-content links (e.g. a vacancy detail's "Müraciət Et" button in `js/vacancies.js`, which links to `cv.html?company=…&vacancy=…`; with those params `js/cv.js` switches the page into an "apply to this vacancy" mode — see the `js/cv.js` bullet below), not from the header.

- `css/global.css` — theme CSS variables, header/nav, hamburger, theme switch, `.btn-primary`, the shared `.glass-effect` card component, the shared form components (`.form-row`, `.form-group` + its `input`/`select`/`textarea`/`input[type=file]` styling, `.form-note` + `.status-success`/`.status-error`, `.botcheck-field`) used by both `contact.html` and `cv.html`, the shared `.site-footer` component and the reusable `.faq-item` accordion component (native `<details>/<summary>` — no JS needed), and the shared responsive breakpoints (1024px, 768px). There is no more `.send-cv-btn` — it was removed along with the header CV button.
- `css/home.css`, `css/about.css`, `css/services.css`, `css/vacancies.css`, `css/industries.css`, `css/contact.css`, `css/cv.css`, `css/faq.css`, `css/notfound.css` — page-specific sections only (layout/hero/grid rules; the actual form-field and FAQ-accordion styling lives in `global.css`, see above). `home.css` no longer has a stats section (removed per request) — `.hero-baku` is now a single vertically-centered block (`justify-content: center` + a `margin-top` nudge on `.hero-content`), not a two-part flex layout.
- `services.html` has 4 `.service-card`s (Executive Search, Professional Recruitment, Talent Assessment, Employer Branding), deliberately kept in **one row on desktop** — `.services-grid` is a fixed `repeat(4, 1fr)` (not `repeat(auto-fit, minmax(...))`, which was tried first and produced an unbalanced 3-then-1 layout). Card padding/icon/text sizes use `clamp()` so the cards shrink to stay in one row rather than wrapping; the grid only drops to `repeat(2, 1fr)` at ≤1024px and `1fr` at ≤768px, once shrinking alone isn't enough. If a 5th service is ever added, revisit this — a 5-wide row would need smaller minimums or a different breakpoint strategy.
- `services.html` also has a `.trust-badges` 2x2 grid below the CTA (90-day guarantee / confidentiality / market intelligence / dedicated consultant) — each `.trust-badge` is a `.card-bg` pill with a solid-orange circular `.trust-badge-icon` (inline SVG, `stroke="#fff"`, not `currentColor` — it's always white regardless of theme since it sits on the solid accent color) and bold text. Collapses to 1 column at ≤768px.
- `faq.html` / `css/faq.css` — dedicated "Tez-tez Verilən Suallar" page; owns the actual FAQ content (5 `.faq-item` entries). The entry point to this page is a short **"FAQ"** link (`.header-faq-link`, in `.header-right` directly before the theme toggle, on every page) — it used to be a "Tez-tez Verilən Suallar" link in the footer (`.footer-faq-link`) and was deliberately moved to the header per request, so don't put it back in the footer. It is never an inline accordion (that was moved out of the footer earlier too). Because it lives in `.header-right`, it appears automatically in the mobile hamburger menu alongside the theme/language controls. An opened `.faq-item[open]` (rule in `global.css`) is framed with an orange border, tinted background and soft shadow so each answer visibly belongs to its question; negative horizontal margin offsets its padding so the text doesn't shift on open, and `faq.css`'s "no bottom border on the last item" rule is `:last-child:not([open])` so the open last item keeps a complete frame. If FAQ questions change, edit them here (and only here).
- `js/main.js` — one `DOMContentLoaded` handler with three independent, null-guarded blocks: language switch, theme + logo, hamburger menu. All shared behavior lives here.
- `js/vacancies.js` — page-specific script for `vacancies.html` only (self-guards via `if (!listEl || ...) return;` if its elements aren't present). Owns the hardcoded `VACANCIES`/`CATEGORIES` sample data and the middle-list→right-detail interaction (click-to-view-detail). Category counts are derived from `VACANCIES` at render time, not hand-maintained. Reads an optional `?category=<id>` URL param on load to open the page pre-filtered to that sahə (nothing on the site links to it anymore since `industries.html` stopped linking here) — this still works since `CATEGORIES`/`activeCategory` are untouched internally, there's just no sidebar control that changes `activeCategory` anymore (see next point). **A Supabase migration for this data is in progress but paused** — see `supabase/schema.sql` and the assistant's saved memory on it; `VACANCIES` is still hardcoded until that's finished.
- **The sort control (`#vacancy-sort-toggle`/`#vacancy-sort-menu`) is a custom div-based dropdown, not a native `<select>`.** A `color-scheme: dark`/`light` fix was tried first (the theory being it should make the native popup follow the page theme) but the user tested it in a real browser and the popup still opened white — `color-scheme` on the `<select>` itself isn't reliable enough for this across browsers. It was replaced with a fully custom dropdown (`.vacancy-sort-dropdown > .vacancy-sort-toggle` button + `.vacancy-sort-menu` absolutely-positioned `<ul>`, wired in `js/vacancies.js`, closes on outside click) so the theme is 100% guaranteed. If another native `<select>`'s popup ever looks wrong on this site, don't reach for `color-scheme` again without testing in a real browser first — prefer this same custom-dropdown pattern.
- `.vacancies-hero` on `vacancies.html` has **no `<h1>` "Vakansiyalar" heading** — it was deliberately removed per request; only the one-line subtitle paragraph remains (the `<title>` still says Vakansiyalar). Don't re-add the heading without being asked.
- `.vacancies-sidebar`'s very first child (before the "Fəaliyyət sahəsi" group) is `.vacancies-sidebar-heading` — a static "Detaylı axtarış" title + one-line hint, scrolls away with the filters like everything else in that box (it's not sticky/pinned).
- **`vacancies.html`'s left column is split into three physically separate boxes**, not one — because "Vakansiya yerləşdir" (and, since added, "Yaddaşa verilmiş vakansiyalar") are navigation/actions, not filters, and were explicitly asked to be kept apart from the 7 real filter groups rather than just listed as 8th/9th ones among them. The grid's actual left cell is `<aside class="vacancies-sidebar-wrap">` (`display: flex; flex-direction: column; max-height: calc(100vh + 50px); align-self: start` — it used to have a fixed `height: calc(100vh + 50px)` with `.vacancies-sidebar` as `flex: 1`, which left a big empty gap inside the filter box on tall screens when all 7 groups were collapsed; per request the height is now content-driven, capped at the same height as the other two columns, so it only scrolls when content exceeds that cap, and it starts at the top of its grid cell instead of floating centered). Inside it, top to bottom: `.vacancies-sidebar` (`flex: 0 1 auto; min-height: 0`, the scrollable one holding the 7 real filter groups, same background/border/scrollbar as always), then `.vacancies-saved-panel` (own card background/border, `flex-shrink: 0` — see the dedicated bullet below for what it does), then `.vacancies-post-panel` (own card background/border, `flex-shrink: 0`) containing a single `.filter-group` for **Vakansiya yerləşdir**. That group reuses the identical header/chevron/collapsible-list markup as the filter groups (so the generic `.filter-group-header` JS handler wires it up automatically, no extra code needed), but its list holds two `.sidebar-menu-link` `<a>` tags instead of checkboxes — plain navigation links (orange text + arrow, not filters) to `post-job.html` and `ad-banners.html`. If a 9th filter group is ever added, it goes inside `.vacancies-sidebar`; if another navigation/action item is added, it goes in `.vacancies-post-panel` alongside Vakansiya yerləşdir, not mixed into the filters. **This box's own colors are deliberately inverted relative to the theme, not just tinted** — a first pass just recolored its header text (orange in dark mode / green in light mode, keeping the normal `--card-bg` background) to stand out from the 7 filter groups above it, but the request was pushed further to a full inversion: in dark mode the box itself is solid white (`#ffffff`, hardcoded, not `--card-bg`) with `var(--bg-color)` (the page's own overall dark-mode background, `#0b1120`) as the text/chevron/link icon color inside — went through two earlier iterations first (yellow `#facc15`, then the standard accent orange `#d97742`) before landing on "match the page's background color" specifically, so the text reads as if it's revealing the page behind the box rather than being an arbitrary accent color; in light mode it's solid near-black (`#0f172a`) with white text inside — `body.light-theme .vacancies-post-panel` flips both the background and (since the box no longer follows the theme's own light/dark border tone) the border color to whichever one reads against the new background. Every visible thing inside it — the "Vakansiya yerləşdir" label, the chevron, and the two `.sidebar-menu-link` texts/arrows — is recolored together via one grouped selector (`.vacancies-post-panel .filter-group-title > span:first-child, .filter-chevron, .sidebar-menu-link`) so they can't drift apart; the links' hover background is also overridden locally (`rgba(0,0,0,.06)` / `rgba(255,255,255,.08)`) since the page's shared `--card-hover` token is tuned for the *normal* card background and would be nearly invisible against this inverted one. The label and links' `font-size` is also bumped to `14px` (from the shared `12px`/`12.5px` the other filter groups use), scoped the same way, so this box reads as slightly more prominent too.
- **A third box, `.vacancies-saved-panel`, sits between `.vacancies-sidebar` and `.vacancies-post-panel`** — "Yaddaşa verilmiş vakansiyalar" (saved vacancies), styled like `.vacancies-post-panel` (own card bg/border, `flex-shrink: 0`). **It is a single button (`#saved-vacancies-toggle`, `.saved-toggle-btn`), not a collapsible list of its own** — an earlier version rendered saved items as a stacked sub-list directly under this button, which was explicitly rejected ("altına yığmasın" — don't have things pile up underneath it); the corrected design has the button act as one more filter toggle, exactly like checking a **Şirkətlər**/etc. box: clicking it sets `showSavedOnly = true` in `js/vacancies.js` and re-runs `renderList()`, which filters the **middle column's** list down to only saved vacancies (combined via AND with whatever other filters/search are active, same as every other filter) — clicking again turns it back off. Every `.vacancy-card` still gets a bookmark `<button class="vacancy-save-btn">` (top-right, absolutely positioned — `.vacancy-card` needed `position: relative` and extra right padding for it) that toggles that vacancy's id in and out of a `talentcore_saved_vacancies` array kept in **`sessionStorage`, not `localStorage`** — explicit requirement ("o sesia bitənədək" — only until the session/tab ends, unlike theme which persists via `localStorage`), don't switch it without checking first. `getSavedIds()`/`setSavedIds()`/`isSaved()`/`toggleSaved()`/`updateSavedCount()` own this: `toggleSaved()` normally just flips the `.saved` class on the matching card's button (cheap), but calls a full `renderList()` instead when `showSavedOnly` is active, since un-saving a card must make it disappear from that filtered view immediately. `updateSavedCount()` keeps a small `#saved-count` badge on the toggle button in sync with how many are currently saved (hidden at zero). Since the toggle button has no list under it anymore, un-saving is done only from each card's own bookmark button (no separate remove affordance in the panel).
- **Middle-column `.vacancy-card`s are deliberately compact (requested: "ölçüsü kiçilt").** Padding is `14px 46px 14px 18px`, title 15px, and the old separate `.vacancy-tags` pill row + bottom "N gün əvvəl" line were removed: a card is now just the title plus one `.vacancy-meta` line — `🏢 company · 📍 location · type · mode` separated by orange "·" dots (a `::before` on every non-date span after the first, so don't hand-write separators) — with the date as the last span (`.vacancy-posted`, `margin-left: auto`) on the same line, right-aligned. The date shows via `formatPostedDate()` as **"Bu gün" / "Dünən" / "30 sentyabr"** (AZ month names, computed as today minus the day count `getPostedDaysAgo()` parses from `posted`) instead of "2 gün əvvəl"; the `posted` strings in `VACANCIES` stay "N gün/həftə əvvəl" and still drive sorting. Cards are AZ-only text like the rest of the generated card content. The card also has a share button (same `.vacancy-share-btn` class and `shareVacancy()` as the detail panel, restyled small/borderless via `.vacancy-card .vacancy-share-btn`) stacked directly **under** the bookmark button in the top-right (`top: 38px` vs the bookmark's `8px`); its click is handled in the `listEl` handler before the card-selection logic (preventDefault + stopPropagation, like the bookmark). The detail-panel share button was kept too.
- **The vacancy detail panel (right column) has a "Paylaş" (share) button next to the title**, in a new `.detail-title-row` wrapping the `<h2>` (the title's own `margin-bottom` moved onto this row so there's no double gap). `js/vacancies.js`'s `shareVacancy(v, btn)` builds the link as `location.origin + location.pathname + '?vacancy=' + v.id` — the same focused-mode URL the "open in new tab" feature already produces, so it always resolves to a clean single-vacancy view regardless of what page/filter state the person sharing was in. It prefers `navigator.share()` (the OS-native share sheet — mobile browsers, some desktop ones) and falls back to `navigator.clipboard.writeText()` with a small "Link kopyalandı" tooltip (`.vacancy-share-btn.copied::after`, styled with the same solid `#141c30`/`#ffffff` floating-popup pattern as `.vacancy-sort-menu` — `--card-bg` is too transparent for a popup that floats over other content) if the Share API isn't available, and as a last resort a `window.prompt()` with the link if clipboard access also fails. No fixed target platform (WhatsApp/Telegram/etc.) was picked on purpose — the request was to let it be shared "hardasa" (anywhere), so a generic OS share/copy is the right level. Since `renderDetail()` fully replaces `#vacancy-detail`'s `innerHTML` on every render, the button's click handling is delegated on `detailEl` itself (not bound per-button), same reasoning as the delegated listener on `listEl` for vacancy cards.
- **The left sidebar's 7 checkbox filter groups are now wired to filter the vacancy list — but this is explicitly temporary test wiring on top of the static `VACANCIES` array, not the final design.** The user asked for this specifically to try the filtering interaction ("statik vakansiyalara bağla... onsuz bu mövzuya ayrıca gələcəm" — connect it to the static data for now, will revisit the topic separately once there's a real backend). Two of the seven groups needed genuinely new per-vacancy data because they don't correspond to anything that already existed:
  - `sector` (15 values, matches the **Fəaliyyət sahəsi** checkboxes) and `jobCategory` (9 values, matches **Kateqoriyalar**) were added to every `VACANCIES` entry by hand, mapped from each job's existing `category`/`company`/title with editorial judgment (e.g. an AtlasBank insurance-product-manager role got `sector: 'banking-finance'`) — these are separate from, and don't replace, the pre-existing 7-id `CATEGORIES`/`category` field that `industries.html`'s cards still use. `level` (9 seniority values, matches **Vəzifə dərəcəsi**) was also added per entry, but left `null` on individual-contributor roles (developers, analysts, specialists) rather than force-fitting them into a management-level taxonomy that doesn't really describe them — expect most checkboxes there to match nothing until real data arrives.
  - The other four groups reuse fields that already existed, via small lookup tables in `js/vacancies.js` rather than new per-entry data: **Şirkətlər** uses `company` directly (already dynamic, see below); **Region** maps `location` display text (`REGION_BY_LOCATION`); **İş qrafiki** maps `type` (`SCHEDULE_BY_TYPE`); **İş formatı** maps `mode` (`FORMAT_BY_MODE`).
  - Matching logic is `passesSidebarFilters(v)`: OR within a group (any checked box in that group is enough), AND across groups (every group with at least one checked box must match) — a group with nothing checked doesn't constrain anything. Wired via one delegated `change` listener on `.vacancies-sidebar` (not `.vacancies-post-panel`, which holds no checkboxes) rather than per-checkbox listeners, so it keeps working for `renderCompanyFilter()`'s dynamically-built company list automatically.
  - **When the real backend/Supabase migration happens** (see `supabase/schema.sql` and the assistant's saved memory), this hand-assigned `sector`/`jobCategory`/`level` data doesn't need to be preserved as-is — it was a best-effort testing aid, not a taxonomy decision. Re-derive it properly against real vacancy data at that point.
- `vacancies.html`'s sidebar is 7 collapsible checkbox filter groups (`.filter-group`, each a `.filter-group-header` button + a `.filter-options` list): **Fəaliyyət sahəsi** (15 broad sectors), **Şirkətlər** (populated dynamically — see below), **Kateqoriyalar** (9 items), **Vəzifə dərəcəsi** (9 seniority levels), **Region** (25 cities/districts), **İş qrafiki** (2), **İş formatı** (3) — **all 7 start collapsed** (Fəaliyyət sahəsi used to default to expanded; that was deliberately changed, don't revert it). All 7 headers are wired generically in `js/vacancies.js` (`document.querySelectorAll('.filter-group-header').forEach(...)`, matched to its list via the header's `aria-controls` attribute — new groups just need that pairing, no JS changes) rather than one handler per group.
- **No vacancy is auto-selected on page load — the right column shows a rotating "our services" showcase until the user clicks a card.** `activeVacancyId` starts `null` (not `VACANCIES[0].id`), and `renderList()` only clears an existing selection (back to `null`) if it no longer matches the current filters/search — it never auto-picks a replacement vacancy. `js/vacancies.js`'s `SERVICES_SHOWCASE` (4 entries, AZ+EN copy matching `services.html`'s cards) auto-advances every 5s via `startShowcaseRotation()`/`renderServicesShowcase()` into `#vacancy-detail`, styled by `.detail-placeholder` in `vacancies.css`. `stopShowcaseRotation()` is called from `renderDetail(v)` for both a real vacancy and the "no results" empty state, so the interval never fires into stale/wrong content. The user's own framing: "sağa lazım olsa sonra reklam qoyacağıq" — this slot is designed to be swapped for a static ad later, so keep the rotation logic isolated in these few functions rather than spreading it through `renderList()`.
  - `#company-filter-list` is the one group that's **not** static HTML — `renderCompanyFilter()` in `js/vacancies.js` builds it from `[...new Set(VACANCIES.map(v => v.company))]` (sorted) at the end of the `DOMContentLoaded` handler, so it only ever lists companies that actually have a posted vacancy, per the request that drove this ("yalnız elan verəndə yerləşdirdiyimiz şirkətlər çıxsın"). If `VACANCIES` changes, this list updates automatically on next load — don't hardcode company checkboxes here.
  - No group shows a "(eyni anda bir neçə seçim edə bilsin)" hint anymore — it was tried on all 7 group titles, then explicitly removed by request. `.filter-group-hint` no longer exists in `css/vacancies.css`; don't re-add it without being asked.
- **The middle column has its own toolbar now, and is one more layer of nesting than before.** The grid's middle cell is `.vacancies-list-panel` (fixed height, flex column), containing `.vacancies-list-toolbar` (search input `#vacancy-search` + sort `<select id="vacancy-sort">`, always visible) above the actual scrollable `.vacancies-list` (`flex: 1; min-height: 0`, same id/class as before so none of the existing click/scroll code in `js/vacancies.js` needed to change). Search matches `title` or `company` (debounced ~150ms); sort has three modes — `newest`/`oldest` (parsed from the free-text `posted` field via `getPostedDaysAgo()`, since there's no real date field — see below) and `az` (`title.localeCompare`). Both re-run `renderList()`, so they compose with the category/mobile-pagination logic already there, but **not** with the sidebar checkboxes (still unwired, per above).
  - `getPostedDaysAgo()` regex-parses strings like `"2 gün əvvəl"` / `"1 həftə əvvəl"` into an approximate day count for sorting, rather than adding a real date field to every `VACANCIES` entry. If new `posted` phrasing is introduced that doesn't match `/(\d+)\s*(gün|həftə)/`, it silently sorts as 0 (treated as "today") — keep new entries to the existing "N gün/həftə əvvəl" phrasing, or extend the regex.
  - The search input's placeholder needed a translation mechanism `.lang` can't provide (it sets `innerHTML`, which does nothing on an `<input>`). `main.js`'s language-switch handler now also walks `.lang-placeholder` elements and sets `.placeholder` from `data-az-placeholder`/`data-en-placeholder` — reuse this class/attribute pair for any future placeholder that needs translating, instead of inventing another mechanism.
- **None of the 3 `vacancies.html` columns use `overscroll-behavior` anymore — it was tried (`contain`) and then deliberately removed.** The idea was to stop scroll from chaining into the outer page once an inner column (sidebar/list/detail) reached its scroll boundary. In practice it also blocked wheel-scroll entirely whenever a column's content didn't overflow (or once it reached the end) — hovering over e.g. the detail panel with a short job description meant scrolling did nothing at all, not even scrolling the outer page. Removed from all three (`.vacancies-sidebar`, `.vacancies-list`, `.vacancy-detail`) so scroll always chains to the page when a column has nothing left to scroll internally. Don't re-add `overscroll-behavior: contain` here without re-checking this tradeoff.
- **Right-clicking (or middle-click/Ctrl-click) a vacancy card opens that vacancy alone in a new tab — a plain left-click still keeps the existing in-page behavior.** Each card in `renderList()` is a real `<a class="vacancy-card" href="vacancies.html?vacancy=<id>">` (not a `<div>`) so the browser's native "Open in new tab"/middle-click/Ctrl-click works with zero JS involvement. The `listEl` click handler checks `e.ctrlKey || e.metaKey || e.shiftKey || e.button !== 0` first and returns early (letting the browser navigate natively) before calling `e.preventDefault()` for a plain left-click, which still just updates `activeVacancyId`/renders the detail in place as before. On load, `js/vacancies.js` reads `?vacancy=<id>` the same way `?category=` is read: if it matches a real vacancy, `activeVacancyId` is set to it, `document.title` becomes `Talentcore | <title>`, and `document.body` gets `vacancy-focused-mode`, which in `css/vacancies.css` hides `.vacancies-sidebar-wrap`/`.vacancies-list-panel`, collapses `.vacancies-layout` to a single centered column, and reveals a `.vacancy-back-link` ("← Bütün Vakansiyalar", in `vacancies.html` between `.vacancies-hero` and `.vacancies-layout`) back to the plain listing. Because `renderList()`'s "clear an out-of-filter selection" check normally looks at the current mobile `pageItems` slice, it's explicitly skipped when `vacancy-focused-mode` is set — otherwise a focused vacancy that isn't on mobile-pagination "page 1" would get wrongly deselected back to the services showcase on load, even though the list itself is hidden in this mode anyway.
- **The 3 columns on `vacancies.html` are deliberately taller than one viewport.** `.vacancies-page`'s padding (`150px 0 80px 0`) and `.vacancies-hero`'s margin are the original values — a first attempt at "make the columns bigger" shrank these instead, which was explicitly rejected ("sıxışdırma deyil" — not compression). What was actually wanted: keep the surrounding spacing as-is, and directly grow the column height past one screen. The height formula is `calc(100vh + 50px)` (not `calc(100vh - 150px)` and not `calc(100vh - Npx)` in general) on `.vacancies-sidebar`, `.vacancies-list-panel`, and `.vacancy-detail` — columns now extend ~300px below the initial fold, which is intentional; don't "fix" this back to a subtracted/viewport-fitting formula without checking first.
- `js/contact.js` / `js/cv.js` — page-specific scripts (same self-guard pattern), both submit via `fetch` to [Web3Forms](https://web3forms.com) (`https://api.web3forms.com/submit`) rather than a backend, forwarding straight to `info@talentcore.az` with no mail client opening. **Both require the same one-time setup step**: their forms' hidden `access_key` input still holds the placeholder `YOUR_WEB3FORMS_ACCESS_KEY` — go to web3forms.com, enter `info@talentcore.az`, and paste the real access key emailed back into *both* `contact.html` and `cv.html` (each JS file refuses to submit and shows an error while its placeholder is still in place). Hidden `subject` inputs set each email's subject line; the visible contact dropdown is named `inquiry_type` rather than `subject`, to avoid clashing with Web3Forms' reserved field name. `botcheck` is an invisible honeypot field for spam bots on both forms. `cv.html`'s file input is named `attachment` (Web3Forms' convention for file uploads) and both HTML and `js/cv.js` cap it at 5MB client-side — Web3Forms' own limit should be double-checked if that changes.
- **`cv.html` has two modes, chosen by `js/cv.js` from the URL.** Without params (reached from a plain link) it is the generic "CV Göndər" candidate form (name, email, phone, optional desired position, CV file, note, consent). The old "Maraqlandığınız Sahə" `<select>` was deliberately removed — don't re-add it. With `?company=…&vacancy=…` (from a vacancy detail's "Müraciət Et") it becomes an application form: `body.cv-apply-mode`, a `.cv-apply-target` card showing the vacancy title + company (filled via `textContent`, not innerHTML), retitled hero/form/steps/privacy note/button ("Vakansiyaya Müraciət", "Müraciət Et"…), the desired-position field hidden+disabled, and the email `subject` set to include the vacancy and company. ### Theming

Dark is the default: `:root` holds the dark values, and `body.light-theme` overrides them. There is no `.dark-theme` rule in CSS — dark is simply the absence of `light-theme`.

`main.js` reads `localStorage.theme` (default `'dark'`) on load and toggles the `light-theme` class. Every page also runs a small inline script as the first thing in `<body>` that applies the same class before first paint, to avoid a flash of the wrong theme (FOUC) — copy this script verbatim into any new page. New theme-dependent styles belong in `global.css` as a variable pair, or as a `body.light-theme .selector { }` override next to the base rule.

The hero/page background photo (`baku_light.jpg`) is tinted per theme via the single `--hero-bg` variable — don't declare `--hero-bg` a second time inside `body.light-theme`, the later declaration silently wins and has previously washed out the light-mode overlay until it was collapsed back to one declaration.

The logo is swapped by JS between `logo.png` (white wordmark, for dark) and `logo_light.png` (navy/orange wordmark, for light) based on theme — `global.css` no longer applies any filter on top of it; don't re-add one, it would double up with the JS swap and invert the already-correct light logo. `main.js` selects **all** `.site-logo` elements (`querySelectorAll`, not `querySelector`) and swaps every one of them — there are currently two per page that has a footer: the header logo and `.footer-logo` (which carries both `site-logo` and `footer-logo` classes, the latter just for sizing). Any new logo `<img>` needs the `site-logo` class to stay in sync automatically.

### Language switching

`.lang` elements carry `data-az` and `data-en` attributes; the `#lang-switch` `<select>` swaps `innerHTML` from the matching attribute. Consequences to respect:

- Values are injected as HTML, so `<br>` inside them works (used in the hero headline) — but the attributes are the translation source and must stay HTML-safe.
- **Every `.lang` element needs both `data-az` and `data-en`.** `about.html` is currently incomplete (22 `data-az` vs 9 `data-en`), so switching to EN writes the string `null` into those elements. Add both attributes when adding `.lang` markup.
- Language is not persisted and resets to AZ on every navigation, unlike theme.
- The element's inline text should duplicate its `data-az` value, since that is what renders before any switch.

## Conventions

- Cards use `.glass-effect` (defined once in `global.css`, used across most pages), driven by `--card-bg` / `--card-hover` / `--border-color`.
- Accent color is `#c4642f` with `#b35624` for hover/border — hardcoded in `global.css` rather than tokenized.
- Sizing leans on `clamp()` for fluid type and spacing; prefer it over fixed px in new rules.
- `baku_light.jpg` is the hero background, set through the `--hero-bg` variable. `baku_light_2.jpg` is currently unreferenced.
